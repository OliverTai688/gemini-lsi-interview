# 介面缺口分析

情境：研究者把連結傳給受訪者，受訪者點進去就能完成整場生命故事訪談。
以下依受訪者的動線列出缺口。✅ = 已補上　⏳ = 尚未處理

## 1. 進入

| | 缺口 | 處理 |
|---|---|---|
| ✅ | 一定要 Google 登入才能用，沒有「給連結就能進」的入口 | 專屬連結 `/i/<token>`，免登入；同一條連結可在任何裝置回來接續 |
| ✅ | 進來之前沒有任何說明：這是什麼、要多久、要準備什麼 | 歡迎頁：訪談說明、時間、環境建議 |
| ✅ | 在 LINE / Facebook 內建瀏覽器打開時麥克風不能用，使用者不知道為什麼 | 歡迎頁偵測並提示改用瀏覽器；後台產生的連結帶 `openExternalBrowser=1`，從 LINE 點開會直接用外部瀏覽器 |
| ✅ | 開始前無法確認麥克風能不能用 | 歡迎頁有麥克風測試（音量條、沒聲音 / 沒權限的提示） |
| ✅ | 錄音同意是進到訪談頁才跳出來 | 併入歡迎頁，勾選後才能開始 |
| ✅ | 預設語言是英文 | 沒選過語言的人依瀏覽器語言決定 |
| ✅ | 研究者給的代號會變成訪談標題顯示給受訪者 | 受訪者看到的是通用標題，代號只在後台顯示 |
| ✅ | 登入 / onboarding / 登出頁沒有多語系，品牌名稱寫的是「Interview AI」 | 三頁都接上多語系，品牌統一為「生命故事訪談」；登入頁標明是研究者登入 |

## 2. 訪談中

| | 缺口 | 處理 |
|---|---|---|
| ✅ | Gemini Live 連線有時間上限，斷線後畫面只會悄悄回到「點擊開始」，受訪者以為訪談結束了 | 非使用者主動停止的斷線會自動重連並帶回逐字稿，連續失敗 3 次才停下來 |
| ✅ | 沒有麥克風權限時，畫面顯示「聆聽中」但其實沒有在收音 | 改成關閉連線並顯示怎麼開啟權限 |
| ✅ | 離開訪談頁（例如去看逐字稿）後，麥克風與連線還在背景繼續 | 離開頁面時關閉連線與麥克風 |
| ✅ | 手機螢幕自動休眠後麥克風會停 | 訪談進行中保持螢幕喚醒 |
| ✅ | 沒有「結束訪談」這個動作，受訪者不知道怎樣算完成 | 「結束訪談」按鈕與確認對話框 |
| ✅ | 受訪者看得到「返回列表」「產生訪談總結」 | 受訪者模式：沒有列表、沒有 AI 總結（API 也擋） |
| ✅ | 手機上標題列的按鈕擠在一起 | 小螢幕只顯示圖示 |
| ✅ | 網址裡的訪談 id 不存在時，畫面是一個存不了資料的空白訪談 | 顯示「找不到這場訪談」 |
| ✅ | 沒有進度：受訪者不知道現在在哪個段落、還剩多少 | 標題列下方的進度條（三個部分 + 目前第幾題）。每回合存檔後由伺服器請模型判斷談到哪一題，不動訪談連線本身，判斷失敗也不影響訪談 |
| ✅ | 麥克風完全不能用時沒有替代方式 | 拿不到麥克風時連線照常建立，自動打開打字欄；平常也可以按「改用打字」。AI 一樣用語音回應 |
| ✅ | 受訪者說話時看不到即時字幕（只有 AI 的回應有） | 顯示「你（正在說）」的即時字幕 |
| ✅ | 字級偏小、灰字對比低，對年長受訪者不友善 | 訪談頁的對話、狀態與提示文字放大，灰字加深 |
| ✅ | 同一條連結在兩個裝置同時開著訪談，沒有處理 | 後開始的裝置接手；先前那個裝置在下一回合存檔時會被告知並暫停（該回合仍會存下來） |

## 3. 結束後

| | 缺口 | 處理 |
|---|---|---|
| ✅ | 訪談結束後沒有任何收尾畫面 | 完成頁：致謝、回顧逐字稿 / 素材、繼續補充 |
| ✅ | 受訪者沒有地方可以撤回 / 刪除自己的資料 | 完成頁可刪除整場訪談（含錄音與素材） |
| ✅ | 回來時不知道上次的進度有沒有保存 | 歡迎頁顯示「歡迎回來」與目前狀態（進行中 / 已完成） |
| ✅ | 錄音是 60 秒一段，下載時是多個檔案 | 素材庫可以「合併成單一檔案」再下載（ffmpeg 重新封裝，不重新編碼） |

## 4. 研究者

| | 缺口 | 處理 |
|---|---|---|
| ✅ | 完全沒有後台，研究者看不到受訪者的資料 | `/admin`：受訪者列表、狀態、訊息數、最後活動 |
| ✅ | 無法產生與管理連結 | 新增受訪者、重新產生連結、停用 / 恢復、刪除受訪者（含所有資料） |
| ✅ | 看不到別人的逐字稿 / 素材 / 總結 | 管理者可讀取所有訪談；不能代替受訪者寫入或開始訪談 |
| ✅ | 連結只在產生當下顯示一次（資料庫只存雜湊） | 連結另外用 `AUTH_SECRET` 衍生的金鑰加密保存，列表上隨時可以再複製 |
| ✅ | 沒有批次匯出、搜尋與篩選 | 搜尋代號 / 稱呼、依狀態篩選；「匯出全部」下載所有受訪者的逐字稿、總結與素材清單（JSON） |
| ✅ | 管理者的操作沒有紀錄 | 新增 / 複製 / 重新產生 / 停用 / 刪除、產生總結、匯出都會留下紀錄，後台底部可以展開查看 |
| ⏳ | 匯出不含錄音 / 影片 / 圖片檔本身 | JSON 裡只有素材清單；檔案要到各場訪談的素材庫下載 |

## 5. 還沒有用真實服務驗證的部分

本機沒有 Gemini / OpenAI 金鑰，瀏覽器測試環境也沒有麥克風，以下只確認了程式邏輯與型別：

- 用短效 token 連上 Gemini Live、自動重連後訪談能接續
- 訪談進行中的錄音混音（麥克風 + AI 語音）
- 白板畫面即時送給 AI 訪談員
- 打字輸入後 AI 的回應（走的是和既有程式相同的送出方式，但沒有實際連線測過）
- 進度判斷的準確度（流程用假的模型回應測過，模型實際判斷得準不準要上線後觀察）
- 產生訪談總結時附上白板圖片
- 合併錄音在 Vercel 上執行（本機用同一個 ffmpeg 執行檔測過；Vercel 的打包設定見 `next.config.ts`）
- iOS Safari 與 Android Chrome 實機

## 6. 需要你決定才能做的

- **素材保存期限**：目前會一直保留到受訪者或研究者刪除。
- **同意畫面與歡迎頁的文字**：需要依實際的研究倫理 / 個資告知調整（`messages/zh-TW.ts` 的 `consent`、`invitePage`）。
